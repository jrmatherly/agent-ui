## Summary

Replaced the dropdown-based ModeSelector with a **Segmented Control** (toggle button group) pattern. This change eliminates the need for inline descriptions that cluttered the dropdown while providing clear visual indication of the current mode and a more intuitive interaction model.

**Issues Resolved:** 2

- Cluttered dropdown with inline descriptions
- Poor discoverability of mode options

## Design Rationale

### Why Segmented Control?

1. **Binary Choice**: Only two options (Agent/Team) - ideal for toggle pattern
2. **Always Visible**: Both options visible without clicking to reveal
3. **Clear State**: Active state is immediately apparent
4. **Faster Interaction**: Single click vs click-then-select
5. **Self-Explanatory**: Icons (Bot, Users) provide visual context without text descriptions

### Visual Design Decisions

| Element | Choice | Reason |
|---------|--------|--------|
| Container | `bg-secondary` with border | Matches sidebar theme |
| Height | `h-9` | Consistent with other sidebar controls |
| Border radius | `rounded-xl` | Matches design system |
| Active state | `bg-background shadow-sm` | Clear visual distinction |
| Inactive state | `text-muted-foreground` | Subdued but readable |
| Icons | Bot, Users (lucide-react) | Self-explanatory metaphors |
| Text | Uppercase, 12px | Matches EntitySelector styling |

### Interaction Design

- **Click handling**: Only triggers change if different mode selected (no redundant state updates)
- **State clearing**: Switching modes clears agent/team selection, messages, and session to prevent stale data
- **Transition**: `transition-all` for smooth visual feedback

## Positive Observations

- Consistent with modern UI patterns (iOS, Android, many web apps use segmented controls for binary choices)
- Removes dependency on Radix Select component for this use case
- Better accessibility - no hidden dropdown state
- Smaller DOM footprint
- Icons provide visual memory aids for frequent users

## EntitySelector Consideration

The EntitySelector still uses the dropdown pattern, which is appropriate because:

- Dynamic number of items (agents/teams list)
- Items have additional metadata (model name)
- Search/scroll may be needed for long lists

However, the inline descriptions could be removed from EntitySelector as well if desired - the model name already provides sufficient context.
